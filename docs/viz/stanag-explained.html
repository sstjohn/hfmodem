STANAG & MIL-STD

A family of HF waveforms for carrying a bit stream through fading and multipath. Known symbols train the receiver; coding and interleaving protect the unknown ones.

Experimental. These diagrams describe implemented geometry, not a measured radio exchange. No live STANAG QSO with hfmodem is demonstrated here, and interoperability remains incomplete.

Related standards, different waveforms

Which modem is on the channel?

“STANAG” means a NATO standardization agreement. It does not name one modulation. Bateleur implements several STANAG waveforms alongside related MIL-STD-188-110 modes. Some identify their rate in a preamble; others require the operator to know the rate and interleaver before decoding.

A single carrier changes its phase and sometimes amplitude in successive symbol intervals. Parallel modes modulate several tones at once. Neither carrier count nor symbol rate alone gives the user data rate.

STANAG 4529 uses the 4285 frame structure at half the symbol rate in a nominal 1240 Hz maritime channel. Its library accepts carrier centres from 800 to 2400 Hz in 100 Hz steps. Transmit placement is further restricted by the station’s declared passband; a receive-only monitor can select a carrier outside that transmit span.

The WBHF name belongs to a wider standards family. This implementation provides only its 3 kHz subset; a radio with a 4 kHz receive filter does not thereby gain a 6–24 kHz WBHF implementation. Later MIL-STD editions extend the standards further. See the official MIL-STD-188-110D with Change 1 for that broader scope; the implemented tables here follow the documented 110C subset.

Time on the air

Data shares the clock with training

A baud is one symbol per second. At 2400 baud, the modem changes symbol every 416.7 microseconds. A symbol can carry several coded bits, but synchronization, probes, error-correcting redundancy and repetition also occupy time. The input rate printed on a mode is not the radio’s instantaneous symbol rate or an application’s delivered throughput.

4285 sends 80 synchronization symbols in every 256-symbol frame, followed by four 32-symbol data runs separated by three 16-symbol reference runs. Data occupies exactly half the symbols. At 2400 symbols/s the frame lasts 106.667 ms; 4529’s identical 256-symbol frame lasts 213.333 ms.

188-110 serial starts with a preamble, then alternates data and probes: 32 + 16 symbols at 2400/4800 bit/s, or 20 + 20 at 150–1200 bit/s. Its 75 bit/s mode instead expands a coded dibit into a 32-chip Walsh pattern. A short preamble lasts 0.6 seconds, and a long one 4.8 seconds. These startup costs matter most for short messages.

4539 carries 256 data symbols and a 31-symbol mini-probe per ordinary frame. It reinserts 72 preamble symbols after every 72 frames, allowing a receiver that missed the start to acquire later. The ordinary frame lasts 119.583 ms. The 72-frame group plus reinsertion occupies 8.64 seconds, giving the input rate: 72 × 256 × 6 × 3/4 ÷ 8.64 = 9600 input bit/s.

WBHF waveform 0 uses Walsh blocks rather than the ordinary data/mini-probe layouts shown in the selector. The other waveform groups have their own probe lengths; treating every “2400 baud” mode as the same frame would lose these distinctions.

In-phase and quadrature

PSK and QAM constellations

PSK carries information in phase. QAM also changes amplitude. These are the actual ordered symbol coordinates in Bateleur’s tables: the military QAM mappings should not be replaced by a generic square constellation. The receiver compares the equalized sample with candidate points and retains soft bit evidence for the decoder.

Protecting a burst

Spread errors before decoding them

HF fading can damage adjacent symbols together. Forward error correction adds redundancy; interleaving moves neighboring coded bits apart before transmission, so a burst of errors can be distributed when the receiver restores their order. Longer interleavers add delay and require more buffering. They do not make the channel error-free.

The serial convolutional code has constraint length 7 and two generator masks, 0x6D and 0x4F, in this implementation’s delay-bit convention, with the first mask’s output transmitted first. Its base rate is 1/2. 4285’s 2400 bit/s path punctures the coded stream; lower rates repeat coded pairs before the convolutional interleaver. Its 32 branches use row permutation (9 × row) mod 32 and delays proportional to branch position.

4539 uses a tail-biting block code and punctures the six-output-bit group with mask 111001 to obtain rate 3/4. It interleaves 1, 3, 9, 18, 36 or 72 frames, named US, VS, S, M, L and VL. The coded block sizes and load increments depend on both rate and interleaver. The uncoded 12800 mode has no interleaver despite its 12800US parser spelling.

The byte interface defaults to least-significant-bit first. An asynchronous sender inserts start, data, optional parity and stop bits, so a receiver must use the matching character format. The physical waveform alone cannot tell whether a decoded byte stream is text, compressed data, a higher-layer packet or something else.

For coded 4285, the implementation’s Annex E framing uses start marker 03873C3C, end marker 4B65A5B2 and a mode-dependent flush. Its implemented flush formula is J × 32 × 32 ÷ (2 × repeat) + 102 bits: 600L has 6246 flush bits, about 10.4 seconds at 600 bit/s. These Annex E readings remain unverified against another implementation. Uncoded 4285 carries a bare bit stream and uses no such message markers.

Three different jobs

A waveform is not a link controller

The modem converts bits to audio and audio back to bits. Its physical layer does not provide ARQ: decoding a message marker says nothing about a recipient’s acknowledgement. Bateleur’s raw host interface offers command and data ports, normally 8310 and 8311. Applications must supply their own meaning and delivery rules.

ALE, automatic link establishment, selects and calls stations on suitable channels. Bateleur’s 2G ALE uses a separate FSK waveform and controller. It is not a 4285 preamble and does not make arbitrary military data traffic readable. The console’s HFLINK operation is documented separately in ALE and selcall.

STANAG 5066 is an HF subnetwork layer above a modem. The implemented edition 1.2 node handles link setup, segmentation, ARQ/non-ARQ delivery and host primitives. Its client interface normally uses TCP port 5066. A supported modem waveform and a local node test do not establish interoperability with a foreign 5066 service; that remains unverified.

The parallel modes have different protection. The 39-tone waveform uses Reed–Solomon coding over GF(16), interleaving and diversity; its data tones run from 675 to 2812.5 Hz at 56.25 Hz spacing, with a separate 393.75 Hz Doppler tone. The 16-tone waveform has data tones from 935 to 2585 Hz at 110 Hz spacing and a 605 Hz Doppler tone; it is uncoded and uses in-band diversity below 2400 bit/s. Their fuller framing and character rules are in the linked protocol notes.

Listen to one family

Choose the decoder you need

The console has distinct receive-only modes. With your radio already tuned, these commands listen through its selected audio input. They do not transmit or automatically acknowledge anything. For 4285 and 4529, choose the actual rate and interleaver used by the sender; a default is only a starting setting.

hfmodem console stanag4285 monitor --mode 1200L
hfmodem console stanag4529 monitor --mode 600L/1700
hfmodem console mil110 monitor --framing 8N1
hfmodem console stanag4539 monitor
hfmodem console wbhf monitor
hfmodem console tone39 monitor --mode 600/33/A10.8
hfmodem console tone16 monitor --mode 1200

--freq is an optional startup dial frequency in kHz, and a peer name can select a configured channel. You can retune the radio itself while monitoring. Monitor mode does not perform in-session CAT tuning. stanag is a convenience alias for one selected Bateleur waveform, not a simultaneous scan of every STANAG: --mode '4529 600L' selects just 4529.

For self-identifying 110, 4539 and WBHF, the monitor reads the preamble rather than accepting a rate restriction. Character framing and byte order still matter. The console shows decoded text or escaped/hex bytes; seeing bytes is not proof that an application checksum or delivery protocol succeeded. See the monitor guide for sources, recording and stopping.

Evidence boundary

What the implementation establishes

The waveform implementations have local round trips, worked-example checks and fading-channel simulations. The protocol notes also report receiver decodes of published foreign 188-110 serial and 39-tone recordings. Those recording checks are narrower than a live QSO, and they do not show a foreign modem receiving Bateleur’s transmissions.

No independent 4285, 4529, 4539 or WBHF interoperability result is established by these diagrams. The 4285 Annex A tables were independently cross-checked against a published decoder, but its Annex E framing still needs targeted recordings. The serial-110 preamble count interpretation and randomizer reset, 4539 scrambler conventions and tail-biting boundaries, and several WBHF preamble choices remain documented verification targets.

The implementation omits frequency hopping, two-channel independent-sideband modes and WBHF widths above 3 kHz. WBHF also omits the optional K=9 code, shortened fixed preamble, shifted-mini-probe late entry and optional end-of-transmission marker. The reverse-engineered mod110 receiver stops at channel bits because its payload coding is unknown.

These pages make no STANAG certification or conformance claim. Simulation error counts are conditional on their recorded channels, lengths and seeds; consult the protocol notes before interpreting a short zero-error run as a performance bound.
